# Lumen · Metro 界面设计

> 目标：让"音乐播放器"看起来像 Windows Phone 8 的 Start 屏——纯黑、锐角、细体大字、
> 一块接一块的瓷砖，一个强调色。全部 UI 代码（约 6000 行）里没有任何图片素材，也没有系统控件。

## 1. 为什么要换掉"实体 CD"

上一版把选歌做成实体 CD：一排碟摊开 → 抽一张 → 翻背面 → 开盒 → 放上转盘。
好看，但每看一张专辑都要走四幕动画，
而且一次只能看一张封面——120 张曲库翻起来像在翻相册。

Metro 的答案相反：**把整个曲库同时摊在屏幕上**。一屏十几张封面，
上下滑就是翻曲库。选歌从"抽一张碟"变成"扫一眼"。

## 2. 视觉 token（`src/metro.rs`）

| 项 | 值 |
| --- | --- |
| 底色 | `#000000`（纯黑，不是 #0A0A0F） |
| 文字 | 白 100% / 58% / 36% 三档 |
| 细线 | 白 10%（列表分隔）/ 18%（控件） |
| 强调色 | `#1BA1E2`（WP8 默认 Cyan） |
| 圆角 | 恒为 0 |
| 瓷砖缝 | 6pt（`GUTTER`），墙离屏幕边 12pt（`MARGIN`） |
| 字号（乘 `k`） | 页标题 Light 42 / 专辑标题 Light 23 / 曲目 16 / 小标题 caps 9~10 |

`k = 屏高 / 760`，夹在 0.86~1.55：Pixel 10a 实测 ≈1.13。
所有间距、字号、图标都乘 `k`，一套代码在大屏小屏上比例一致。

字体三档全部使用小米 **MiSans**（嵌入 APK，不依赖系统字体）：

| 族 | 字重 | 用途 |
| --- | --- | --- |
| `metro_light` | MiSans-Light | 大字标题（页标题 Light 42 / 专辑标题 Light 23） |
| `Proportional` | MiSans-Regular | 正文（曲名 / 艺人 / 说明） |
| `metro_semi` | MiSans-Demibold | 瓷砖标题、小标题 caps（大写 + 字距） |

MiSans 覆盖简体中文 + 拉丁 + 常用繁体，一套文件即可，不需要中西文分档回落。
字体来源：`小米字体/MiSans.zip`（小米官方免费商用授权），三档字重放在 `assets/fonts/`。

## 3. 瓷砖墙的排布

列数 = `round(宽 / 215)`，夹在 3~6（Pixel 10a 竖屏 3 列），单元格为正方形：

```
unit = (宽 - 2·MARGIN - (列数-1)·GUTTER) / 列数
```

砖的尺寸统一 **1×1**（等宽网格，节奏一致）。落位用"最低列优先、并列取最左"：
对每块砖枚举可放下的起始列，取 `max(col_y[c..c+w])` 最小的那一列，墙能严丝合缝地填满。

> 早期版本用"每 11 张插一块 2×2 大砖、一块 2×1 宽砖"的错落布局（更像 WP Start 屏），
> 后来改为纯 1×1——等宽网格更整齐，也不会因为大砖插队而让某列突然变长。
> 落位算法保留（1×1 下退化为"从左到右、哪列低放哪列"）。

## 4. 进场：turnstile 翻砖

WP 的 Start 屏第一次滑进来时，砖是绕自身中线从 −90° 翻到 0° 的。这里照做：

```
yaw = -(1 - appear) · (π/2) · 0.9
corners = flip_quad(rect, yaw)     // 绕 Y 轴 + 1100pt 焦距透视
```

* `appear` 由 `Timeline::item(order, 0.030, 0.30)` 给出——相邻两块错开 30ms，单块 0.30s；
* 只给屏幕上这批砖做（最多 15 块），滚下去的不重播；
* 翻的过程只画图不画字；`appear > 0.55` 之后文字才淡入，避免文字跟着斜切变形；
* **只在冷启动播一次**（`goto(Home)` 不再 `tl.reset()`）——之前每次返回首页都重播 1.6s 翻转，
  翻页本身不卡，但"每次返回都重新翻一遍"被感知成卡顿。

## 5. 标题反色（不铺遮罩）

瓷砖标题直接压在封面上，**没有压暗层**——遮罩会把漂亮的封面变成一团黑。
可读性靠"选对字色"：

1. 封面到达时（`Msg::Cover` 由 worker 线程算好 `ink` 一并送回，UI 不再逐像素扫描）；
2. 采样区就是文字真正压住的那块：`y 76%~99% / x 0~72%`；
3. 分数 = `128 + 127 × (白字会糊的像素占比 − 黑字会糊的像素占比)`，
   亮像素（>150）算"白字会糊"，暗像素（<90）算"黑字会糊"；
4. `> 128` 用近黑字 `#121212`，否则用白字。

用占比而不是平均亮度，是因为封面上常有一块极亮或极暗的主体（白桌布、黑西装），
平均值会被它带偏；占比统计的是"文字底下有多少比例不适合这个颜色"。
高频拼贴的封面（亮暗各半）无法两全，这是已知限制。

## 6. 手势与滚动

首页只有**一个** gesture（覆盖瓷砖区），拖动滚墙、点击开专辑都从它来：

* `dragged()` → 直接跟手（1:1，不插值），出界给 45% 阻尼；
* `drag_stopped()` → 手指速度交给惯性（`step_inertia`：`v *= exp(-4.6·dt)` 衰减、
  1/240s 固定子步积分、到边指数回弹吸附）；
* `clicked()` → 用坐标手动命中瓷砖（这样"按在砖上拖"不会变成"点开专辑"）；
* 桌面端滚轮直接跟手，不做惯性。

不用 `ScrollArea` 的原因：里面的按钮会吃掉 press，导致"按在砖上就拖不动"。

**进场保护**：前 0.5s 忽略所有点击和拖动。桌面窗口刚出现时 winit 可能带着上一次的指针状态，
不挡的话会出现"刚打开就自己翻到某张专辑 / 自己滚下去一段"。

## 7. 翻页

一条弹簧 `nav`：0 首页 / 1 专辑 / 2 播放。

| 页 | 位移 |
| --- | --- |
| 首页 | `-W · nav`（0 → −W，向左退出） |
| 专辑 | `nav ≤ 1`: `W·(1-nav)`（右侧滑入）；`nav > 1`: `−W·(nav−1)`（向左退出） |
| 播放 | `W·(1-(nav-1))`（右侧滑入） |

返回时方向相反，正好符合"前进从右边来、后退往右边走"。
三页都铺满纯黑底，叠着画也不会有穿透。弹簧参数 `210 / 26`（约 300ms，末端不过冲）。

## 8. 页面结构

### 首页

```
LUMEN                                       已登录（状态标识）
专辑   N 张专辑
┌────┬────┬────┐
│1×1 │1×1 │1×1 │   ← 瓷砖墙（等宽方砖，滚动区）
├────┼────┼────┤
│1×1 │1×1 │1×1 │
...
└────┴────┴────┘
[封面] 曲名 / 艺人                        ▶   ← 常驻播放条
```

### 专辑页

返回箭头 + `ALBUM`；封面（内容列宽 50%，封顶 300pt）在左，标题（Light 23，最多两行）在右；
下面是整条强调色的"播放全部"，然后 `TRACKS · N` + 细分隔线的曲目表。
当前曲目用强调色 + 左侧 2px 竖条标记。

**折叠头图**：列表往上滑，封面从 300pt 缩到 108pt、播放键和列表整体上移，
可见行数从 4 行涨到 8 行；标题在缩到 60% 之后收成一行，和缩小的封面配平。
滑回顶部封面自动长回来。

**列表惯性**：曲目表和首页瓷砖墙共用一套物理（`step_inertia`）——拖拽 1:1 跟手、
松手把手指速度交给惯性（`exp(-4.6·dt)` 衰减）、1/240s 固定子步、出界 45% 阻尼 + 回弹吸附。
之前这里用的是弹簧追目标位置，松手即停，滑长列表像"按页翻"。

几何上有一个必须遵守的约束：**行的屏幕位置永远是 `list_top₀ + i·row_h − s`**（s = 手势位移），
塌陷只改变可视区顶端（`list_top = list_top₀ − c`，c = 塌陷量），行的绘制偏移用 `s − c`。
这样手指拖 1px，行就跟着走 1px，不会因为"头图在缩"而变成 1.6 倍速的错觉；
可滚上限也能消掉 c：`max = list_top₀ + rows·row_h − clip_bottom`。

### 播放页

`NOW PLAYING` + 序号；封面；曲名（Light 26）+ "艺人 · 专辑"；
一条 2px 进度线（已播部分强调色，右侧显示剩余时间）；三个细线图标（播放键用强调色）；
底部 `UP NEXT` 预告下一首。

**歌词（按方向自适应）**：`wide = 屏宽 >= 屏高`（横屏判断，不用固定阈值）——

* **横屏**（宽 ≥ 高）：Apple Music 式双栏。左栏封面 + 曲名/艺人 + 2px 进度线 + 三个控制键 + UP NEXT；
  右栏整列歌词，顶部 `LYRICS` 小标，歌词随播放进度自动滚动、当前行高亮；
* **竖屏**（宽 < 高）：封面居中在上，曲名/进度/控制依次往下，**歌词在封面下方整屏宽常驻显示**
  （早期是"歌词和封面共用一块方形区域、点按切换"，竖屏双栏会被压到每行只剩几个字，已废弃）。

歌词本身是 **Zune 式**的：

* 歌词由后台线程用 OpenSubsonic `getLyricsBySongId` 取，解析成 `(start, text)`；
  服务端说不同步但文本里带 `[mm:ss.xx]` 时走本地 LRC 解析兜底；
* 当前行停在面板 **42%** 高度（略高于中线，给下面留出"接下来"的暗示），
  亮白 100%，上下行按距离衰减到 15%；当前行左侧一条 2pt 强调色竖条，
  折成两行的句子竖条也跟着变高；
* 换行时整块用弹簧（130/26）滑过去，不是跳变——这是"Zune 平滑滚动"的关键；
  换歌则直接落位，不从上一首的位置滑过来；
* 开唱前（还没到第一句）和纯文本歌词都整体压暗、没有当前行，避免假装在高亮；
* 没有歌词 / 取失败 → 保持封面，点什么都不会变；歌词到得比封面晚时，会淡入。



### 登录

`SETTINGS` + "连接曲库"；三行下划线输入框（只有一条线表示这里能打字）；
整条强调色的"连接并同步"；启动未登录时显示，登录成功自动关闭。

## 8.6 滚动手感与掉帧（2026-11-17 重做）

**手感**：原来首页滚动是"弹簧追目标位置"——松手时弹簧速度是 0，会先顿一下再动，停下又是硬着陆。
现在换成分段模型：

| 阶段 | 做法 |
| --- | --- |
| 拖拽 | 1:1 跟手，不插值、不加弹簧；出界给 45% 阻尼（手指能感觉到到头了） |
| 松手 | 手指速度直接交给惯性，按 `v *= exp(-4.6·dt)` 衰减（约 1 秒到 1%，接近 Android 的 normal fling） |
| 到边 | 速度衰减更快（-10·dt），并夹在 ±120px，随后指数回弹吸附 |
| 积分 | 每帧切成 1/240s 子步做固定步长积分，帧间隔在 15~20ms 抖动时轨迹也不变 |

**掉帧**：真机上原来每滑几下卡一下（单帧 34~50ms）。逐层计时后定位到四处：

1. **字体图集**：预热用的是 `proportional`，而瓷砖的艺人行用的是 `metro_light`
   （另一套中文字体文件），等于没预热——每出现一个新艺人就重排一次字体图集，5~50ms。
   现在按"画的时候真正用的 FontId"预热，`120 张 × 3 字体`，每帧 3 张，1 秒内跑完；
2. **程序化封面**：联网时也在给还没到货的封面现场 `make_art(256)` + 上传纹理（10~20ms/张）。
   现在联网时一律不生成，先显示封面主色的纯色砖；
3. **封面纹理**：`Artwork` 里那张给毛玻璃用的模糊小图没人用了，每次建纹理却仍要
   降采样 + 三次模糊；删掉后每张封面只做一次上传；
4. **滚动期上传**：手指按着/惯性滑行时不碰纹理，落定后每帧只补 1 张，并给新图 80ms 淡入。

另外把 eframe 的 vsync 打开（帧间隔天然等于屏幕刷新率），每帧按 16ms 递请求。

| 指标 | 改之前 | 现在 |
| --- | --- | --- |
| 滑动帧率 | 48~53 fps，每 8 帧掉 1 帧 | **59~60 fps，8/8 次滑动零掉帧** |
| 最长帧 | 34~50 ms | **17~20 ms** |
| UI 线程 CPU | 1.5 ms | 3~4 ms（多出来的是预热后的排版，仍在 16.7ms 预算内） |

> 面板支持 120Hz，但系统把这个应用锁在 60Hz（`dumpsys display` 里
> `mActiveModeId=3`），`ANativeWindow_setFrameRateWithChangeStrategy(120, ALWAYS)` 返回成功也不切模式。
> 既然拿不到 120，就**按 60fps 作为目标帧率**：vsync 定节拍、每帧按 16ms 递请求、
> 所有动画都按 16.7ms 的预算去排。系统里如果哪天放开高刷，把 `request_repaint_after(16_000)`
> 改成 8ms 即可跟上。

**按 60fps 排的其它几处：**

| 场景 | 刷新策略 |
| --- | --- |
| 首页滑动 / 翻页 / 进场 / 封面淡入 / 手指按着 | 每帧（16ms） |
| 播放页在看、但没在拖进度 | **240ms 一次**：2px 进度线走 1 像素要半分钟，不值得为它整屏重画（省电） |
| 完全静止 | 400ms 轮询（等远端消息） |

**字体图集的隐藏坑**：epaint 在图集占用超过 **80%** 时会把整张图集和所有 galley 一起清空
（`Fonts::begin_pass`），下一次绘制所有文字都要重排——比不预热还糟。所以预热不是越多越好：
现在只预热「首页瓷砖」这一批（标题两种字号 + 艺人），并在打开专辑时顺带预热这一页的几条文字，
每帧排 8 条、一旦图集占用超过 50% 立即收手。实测预热完图集只占 1%，离清空阈值很远。

**剩下的一次性代价**（不在连续动画里，可以接受）：

* 冷启动后约 1 秒内有一次 ~50ms 的长帧（首批封面纹理上传），此时画面正是"砖块淡入"；
* 每张专辑**第一次**打开时有一帧 ~30~48ms（这一页的字形第一次光栅化），发生在页码滑入的过程中。

## 9. 性能

| 手段 | 说明 |
| --- | --- |
| 只画可见砖 | 屏幕外（外扩 60pt）直接 `continue`，120 张砖每帧只画十几张 |
| 纹理窗口 | 只给屏幕上这批砖保留 `TextureHandle`（外扩一屏预读 + playing_album + selected），其余**释放纹理**（`art[i] = None`） |
| 每帧限量 | 纹理上传 **2 张**；联网时不生成程序化封面（真封面几帧就到） |
| 帧预算守卫 | 上一帧 CPU >10ms 时这帧不做纹理工作；手指按着/惯性滑行期间完全不动纹理；**封面未加载完时不受 CPU 阈值限制**（否则 warm 阶段会让封面永远纯色块） |
| 文字排版 | 只走"一次 layout"的快路径（`ellipsize` / `text_wrap_bottom`），不再逐字试排 |
| 重绘节拍 | 动画 16ms / 播放页静止 240ms / 完全静止 400ms |

## 10. 已知取舍

* 瓷砖上的文字会和封面自带的文字撞车（杂志风封面尤其明显）——不加遮罩就无法完全避免；
* 没有汉堡菜单 / 侧栏：Metro 的层级就是"一页一页往里进"，登录 / 退出在右上角「已登录」标识里。

## 11. 动效（0.3.0 统一）

Metro 的手感是"快、直、无过冲"；Zune 的手感是"慢一点、收得稳"。两者叠起来的做法是：
**只用一个时长刻度 + 两条缓动 + 三档时长**，任何动画都从这里取，不写魔法数字（`src/anim.rs`）。

| 令牌 | 值 | 用在哪 |
| --- | --- | --- |
| `dur::PRESS` | 100ms | 按下 / 悬停反馈（手指底下必须立刻有反应） |
| `dur::FAST` | 160ms | 播放/暂停图标交叉淡化、封面淡入、错误提示 |
| `dur::BASE` | 220ms | 内容切换：曲目列表进场、退出面板展开 |
| `dur::PAGE` | 300ms | 页面转场 |

两条缓动：

* **进场** `ease_out_quint`（1−(1−t)⁵）：起步快、尾巴长，Metro 的指数缓出；
* **进出手感** `ease_in_out_quart`：两端都收得住，Zune 那种"沉"的淡出。

**一律不过冲**：页面转场从弹簧换成 `Tween`（可中断、从当前值续算），不再有回弹；
回弹只保留给直接操作（滚动惯性 `step_inertia`、歌词弹簧）。

各处落地：

| 场景 | 做法 |
| --- | --- |
| 页面转场 | 三页按 `nav` 平移，300ms 指数缓出；中途再点另一页从当前位置续算，不跳 |
| 瓷砖进场 | −72° turnstile 翻入，单片 260ms、错峰 22ms（最多 12 片，约 0.55s 收完） |
| 封面到货 | 180ms 淡入（从 0.35 透明度起，避免黑闪） |
| 曲目列表 | 220ms 按行错峰淡入（每行差 2 行的时间），曲目到货不再硬切 |
| 播放/暂停 | 两个图标 160ms 交叉淡化；按下时图标略缩 + 极淡圆底 |
| 按钮 | 按压/悬停统一 100ms 缓出（瓷砖、上一首/下一首/播放、迷你条、连接按钮、返回箭头） |
| 退出面板 | 220ms 淡入 + 上移 10pt；入场未完成（<0.65）不接受点击，避免误触 |

**减弱动效**（可访问性）：读取系统的 `animator_duration_scale`（设置里的「移除动画」/开发者选项动画缩放），
启动时缓存一次；为 0 时所有补间直接到位、瓷砖不做翻转、封面不做淡入、歌词弹簧直接落位。
桌面调试可用 `LUMEN_MOTION=off` 模拟。

**性能**：所有新增动效都只是 alpha / 位移，不新增纹理与排版；`animating` 里带上新补间，
只有真的在动时才 16ms 一帧，静止仍是 240/400ms。

## 12. 封面上的文字（0.3.1）

Metro 的瓷砖把标题直接压在封面上，不铺整块遮罩——前提是"字压在什么颜色上"要算准。

**量什么**（`model::Ink::sample`，在解码 worker 里算一次，UI 只读结果）：

* 对文字块区域逐像素算**白字 / 黑字各自的 WCAG 对比度**，统计"离 4.5:1 还差多少"（缺口）；
* 整块按 **3×3 分格**，取**最差一格**——整块平均会掩盖"白字正好压在白色大字上"的局部冲突；
* 水平亮度跳变（边缘密度）作为"花哨程度"的补充惩罚。

**怎么用**（`draw_tile`）：

| 读数 | 处理 |
| --- | --- |
| 一种字明显缺口小 | 用那种（浅字纯白 / 深字近黑），干净封面不压底 |
| 缺口都大 / 封面很花 | 垫一层压底：浅字压黑、深字压白，3 段递进当渐变，只罩文字块 |
| 任何情况 | 每行再叠一层 1px 反色投影，兜住局部高光 |

**排版**：标题 12.5pt（大砖 17pt）最多 2 行，艺术家 10pt（大砖 11.5pt）1 行；
行高 1.28，标题与艺术家间距 3pt；艺术家贴底、标题在它上面，标题被裁时不会吃掉艺术家。
全部 `ellipsize` / `text_wrap_bottom`，一次 layout 不试排。

> 之前的判据是"标题区平均亮度 >128 就用黑字"，白底大字的封面会被判成白字（反色），
> 而且手机上小砖根本不画艺术家——这两个问题都在 0.3.1 修掉了。

## 13. 曲目列表滚动（0.3.2）

列表不是 `ScrollArea`，是自己算的物理（`geometry::step_inertia`，和首页瓷砖墙共用一套）。

**三段式**：

1. **滑行**：`pos += v·dt`，`v *= exp(-5.2·dt)`（时间常数约 190ms）；
2. **越界回弹**：近似临界阻尼弹簧（刚度 260、阻尼 0.95×临界）拉回边界，约 200ms、不过冲；
   上下两端同一套参数，手感一致；
3. **静止**：速度 < 4 归零、贴边，不出现"最后一像素抽搐"。

**输入**：

* 速度估计用 45ms 时间常数的一阶低通（`alpha = 1 - e^(-dt/0.045)`），快滑慢滑都跟得上；
  松手速度上限 4200；
* 拖拽橡皮筋：越靠近边界阻尼越大（1:1 → 0.15），最多拉出 140pt。

**绘制**：

* 列表项按到视口上下边界的距离淡出（上 14pt、下 20pt，`smoothstep`），
  序号/标题/时长/分隔线/当前曲目的强调竖条一起淡——滚出视野是"化开"而不是"被裁断"；
* 头图折叠时标题从两行收成一行，阈值 0.65 进、0.55 出（滞回），避免停在阈值上抖动。

## 14. 迷你播放条的封面（0.3.3）

迷你条左侧那块方砖**永远画一样东西**，只是内容不同：

| 状态 | 画什么 |
| --- | --- |
| 真封面已上传 | 纹理，按 `art_fade` 从底色淡入 |
| 加载中（纹理还没到） | 封面色块（`tint`，没有就按 `hue` 生成） |
| 没有封面数据（`coverArt` 为空） | 同上，色块 |

顺序是**先铺色块再叠纹理**，所以任何一帧都不会出现"空洞"；切换专辑/切歌时也只是
色块→封面的交叉淡入，不会闪白或闪黑。

索引与取图规则：

- 迷你条永远指向 `playing_album`（正在播的专辑），不是 `selected`（当前在看的）；
- 曲库被整体替换（重连/重登）时 `playing_album` 清空，避免旧下标越界或显示成别的专辑；
- `draw_bar` 对下标再做一次夹取，任何情况下都不会越界；
- `maintain_art` 无条件优先给 `playing_album` 插队要封面，不排在批量队列后面。

## 15. 长歌名（0.3.4）

原则：**短名字不动，长名字不外溢、不遮挡、能读全**。按场景用两种手段，避免"到处都在滚"。

| 场景 | 做法 |
| --- | --- |
| 曲目列表行 | **统一 16pt**（不随长度缩放）；放不下的在列表**停稳且整行可见**时跑马灯，滚动/甩动时显示省略号 |
| 播放页大标题 | 26pt，固定；跑马灯（始终） |
| 迷你条歌名 | 12.5pt，固定；跑马灯（始终） |

> 0.3.4 曾经用"按宽度缩字号"处理长标题，结果短标题显得比长标题大（同一个列表里字号不一致）。
> 0.3.5 起**字号只由层级决定，不由内容长度决定**：长名靠跑马灯，短名保持原样。

跑马灯规则（`m::marquee`）：

- **停 1.1s → 缓动滑到末尾 → 停 1.1s → 缓动滑回**，用 `ease_in_out_quart`，不跳变、不循环闪烁；
- 速度 18~26pt/s（字号越大越慢），文字在 `rect` 内垂直居中、水平裁剪；
- 相位按"正在播的曲目"统一：换歌从头开始，播放页 / 迷你条 / 列表里那一行永远同步；
- 只有真在滚动时才以 33ms 请求重绘，其它时候维持 240 / 400ms 的静止节拍。

列表里非当前行错开 0.7s 相位，避免整屏同频滑动；宽度全部取自 layout，
竖屏 / 横屏都是同一套规则。

## 16. 多碟专辑：按碟分页（0.4.0）

> 验证对象：坂本龍一《/04 /05》（2 碟 14+14）、上海烛龙《在水一方》22+24+23+25、
> 《天予风流》23+26+29+20、《榣山遗韵》23+24+28+26。

### 16.1 数据

- `Track.disc: u16`，来自 Subsonic `song.discNumber`（缺省 1）；
- 拉取专辑详情后**按 `(disc, track)` 排序**再入库 —— 同碟曲目必须连续，
  否则"按碟切页"和"绝对下标播放"都对不上；
- `Album::discs() -> [(碟号, 起始绝对下标, 曲目数)]`，`Album::disc_of(ti)` 反查。

### 16.2 布局

单碟：维持原样（`TRACKS · n` + 列表从 `play_btn + 62k` 开始）。

多碟：在"播放全部"下方加一条标签带（高 28k），列表整体下移 36k。

```
[播放全部]
DISC 1   DISC 2   DISC 3   DISC 4     ← 当前碟：强调色 + 2pt 下划线
────────────────────────────────────
DISC 2 · 24 首                          ← 小标从 "TRACKS · n" 换成碟信息
01 …                                   ← 编号每碟从 01 起
```

标签均分列宽（最多 118k），4 碟在手机上刚好一行放下；不换行、不截断。

### 16.3 手势

- 点标签：`switch_disc`，列表回顶、`disc_anim` 从 ±80k 滑回 0（`dur::BASE`）；
- 列表左右滑：按下后先看**主方向**（位移 > 12k，|dx| > |dy|·1.15 判为横向），
  横向就完全不动列表、纵向就完全不管横向——避免"一边滚一边翻页"互相打架；
- 横向拖动跟手平移（上限 60% 列宽），松手过 1/4 列宽翻页，否则弹回；
- 翻页后新碟从手指来的方向滑入（往左甩 → 新碟从右边进），与系统"翻页"的心理模型一致。

### 16.4 播放

列表行只有"本碟内下标"，点击时换算成整张专辑的绝对下标再 `play_track_at`。
`starts` / `total_secs` / `track_bounds` / 上一首下一首仍按整张专辑算，
所以**跨碟是连续播放**的；播放到别的碟时，如果正看着这张专辑，`disc_view` 自动跟过去。

### 16.5 滚动

`max_scroll` 按**当前碟**的曲目数算，不再用整张专辑的总数——
否则切到只有 20 首的碟 2 时，会多出一大段空白可滚。
## 17. 屏幕圆角与系统栏（0.4.3）

Pixel 10a：屏幕 1080×2424，**底部圆角 R=115px（43.8pt）**，挖孔 cutout top 152px；
手势导航 navigationBars 底 63px，三键导航 126px。

### 17.1 迷你条为什么要内缩

条本身铺满整宽（Metro 的边到边），但贴底的内容会落进圆角的裁切弧：
圆角中心 `(R, H-R)`，内容底边离屏幕底 `d` 时，弧在水平方向吃掉

```
inset = R - √(R² - (R-d)²)
```

`d = 7k + 底部系统栏`，再加 2pt 余量、与基础 8pt 取大。实测 **20.2pt**：
缩略封面左边缘在 x=20.2pt，正好在弧外。

### 17.2 安全区数据来源

| 来源 | 用途 |
| --- | --- |
| `DisplayCutout.getSafeInsetTop` | 挖孔/刘海 |
| `WindowInsets.getInsets(Type.systemBars())` | 状态栏 + 导航栏（手势 63px / 三键 126px） |
| `Display.getRoundedCorner(POSITION_BOTTOM_LEFT).getRadius()` | 底部圆角半径 |

每秒复查一次（`current_insets()`），变化就更新布局并重读圆角；
`configChanges` 里补了 `navigation`，避免系统栏变化时重建 Activity（重建会丢 GL surface）。

### 17.3 已知限制

**运行中切换导航方式**（手势 ↔ 三键）会让 GL surface 失效，画面变黑，需要重启 App；
冷启动在两种模式下都正常（三键下迷你条自动抬到导航栏上方）。
这是 winit/GameActivity 的 surface 重建问题，与圆角适配无关，后续单独处理。

## 18. 热启动卡启动封面（0.4.4）

现象：从后台点回应用只看到图标/启动封面，但音乐还在放。

状态机：音频在**独立的 `lumen-audio` 线程**里，UI 崩溃/卡住都不影响它；
系统的启动封面（splash）要等**第一帧真正提交**才消失。所以"有声音、没界面"=
进程活着、音频线程正常，但 UI 这条线没有产出新帧。

两条最可能的路径与对策：

| 路径 | 机制 | 对策 |
| --- | --- | --- |
| 循环没排帧 | Resume 后 eframe 没收到重绘请求，一直停在 splash | UI 看门狗：音频在播且 2s 无帧 → 跨线程 `request_repaint()` |
| Activity 重建 | 系统销毁并重建 Activity → `android_main` 二次进入，旧 eframe 循环仍占着 surface 并继续放音频 | 重入检测 + `ViewportCommand::Close` 关掉旧循环，释放 surface 与音频 |

诊断日志：

```
app     : android_main entered
app     : android_main re-entered (entry #2) — 关闭上一轮事件循环
app::app: closing previous eframe loop (activity recreated)
app::app: ui watchdog: no frame for 2400 ms while playing — request repaint
```

验证：后台 5s / 30s / 2min 各来回 3 次，界面都在 1s 内出现；正常路径不应出现
`ui watchdog` 告警。若出现，抓 `android_main|eframe failed|ui watchdog|GameActivity: on`
四类日志即可判断是"没排帧"还是"重建"。

根治仍需前台服务（MediaSession）：没有 FGS 时系统可以在后台回收/重建 Activity，
本节的措施是兜底而不是替代。

## 19. 非正方形封面（0.4.5）

封面比例来自解码后的图像（`Artwork.aspect = w/h`），所有展示位都按 **contain** 摆放：
保持比例、显示完整画面，留白而不是裁切。

```
fit_within_tl(box, aspect)  左上对齐 contain（专辑页，信息列跟着封面右缘走）
```

| 场景 | 方图 | 横版（如《自彼此遇到》《蓦兰》） | 竖版（如「中国交响世纪」） |
| --- | --- | --- | --- |
| 首页瓷砖 | 原样铺满 | 上下留哑光衬纸，文字收进图片内部 | 左右留衬纸，文字仍在图片底部 |

## 20. 悬浮迷你播放条（0.4.6）

### 20.1 为什么要重构

旧做法是"每个页面自己画一条"：`draw_home` / `draw_album` 各自调用 `draw_bar`，还要跟着页面
`dx` 平移。结果是：翻页时条跟着页面滑（看起来像闪）、页面切换时条会先消失再出现、
专辑页在"有曲目/没曲目"之间切换时底部高度突变（列表跳动）。

现在改成**悬浮层**：在 `ui_root` 里最后画一次，位置只由 `lay_bar(screen)` 决定：

```rust
if self.page != Page::Playing && self.bar_visible() {
    if settled { self.bar_input(ui, screen); }   // 命中区 = 同一矩形
    self.draw_bar(&painter, screen, lay_bar(self, screen));
}
```

### 20.2 显示规则

| 条件 | 行为 |
| --- | --- |
| `bar_visible()`（在播 / 有播放专辑 / 当前专辑已加载曲目） | 显示，底部预留 `BAR_H*k + bar_bottom` |
| 什么都没有（冷启动） | 不显示、不预留，列表铺满 |
| 播放页 | 不显示（整套播控在那儿，画了会压歌词） |
| 登录页 | 不显示 |

### 20.3 播放键语义

`toggle_play` 先看"有没有真正起过音频"（`has_audio`）：

- 没有 → 直接 `play_in_album(当前专辑, 0)` 起播（而不是只把图标翻成"播放中"）；
- 有 → 正常暂停 / 继续；整张播完时 `has_audio` 复位，再点播放是重新开始。

## 24. Material 3 Expressive 动效与预测性返回（0.5.0）

### 24.1 弹簧

| 档位 | 刚度 | 阻尼比 | 用途 |
| --- | --- | --- | --- |
| `Spring::spatial` | 240 | 0.82 | 页面、碟片、位移类（末端过冲 5~8%） |
| `Spring::effects` | 1600 | 0.95 | 透明度、图标、行淡入（快、不冲） |

### 24.2 预测性返回

```
系统手势 ──progress 0..1──▶ back.rs(原子) ──▶ sync_predictive_back
                                     └─ nav.drag_to(from + (to-from)*p)
松手 ──onBackInvoked──▶ go_back()（弹簧走完）
取消 ──onBackCancelled──▶ nav.drag_end(from, 0)（弹回）
```

覆盖顺序：确认面板 → 设置页 → 播放页 → 专辑页 → 首页（退出）。
Android 13 只有最终提交（没有进度）；桥装不上时退回 KEYCODE_BACK。

- 首页 2 列卡片；专辑页 filled 按钮 + 分段 chip + 圆角行；播放页 M3 滑块 + 圆形传输键。
- 圆角封面：`Artwork::from_image` 上传前把 alpha 抠圆（1px AA），绘制端不再做遮罩。
- 仍待迁移：设置/登录页排版、歌词文字配色、图标仍用自绘线条字形。

## 26. Yoin 式底栏（0.6.1）

- 一条悬浮药丸里放三个槽位：左「首页」、中曲目胶囊、右播放/暂停。

- 换歌：`bar_slide` 空间弹簧 1→0，旧名在左、新名从右推入。
